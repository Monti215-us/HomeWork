# Создание инфраструктуры
## <a id="YC">Регистрация в Yandex Cloud</a> 
Yandex Cloud использует личный аккаунты Яндекс ID или аккаунты Яндекс360 при регистрации. До создания первых виртуальных машин через Terraform в YC потребуется: 
1. Создать платежный аккаунт
    - Требуется, даже если планируется использовать только грант, который выдаётся при регистрации. 
2. Создать организацию
    - Часть иерархии. 
3. Создать облако
    - id облака потребуется в terraform. 
    - Часть иерархии. 
4. Создать каталог
    - id каталога так же потребуется в terraform. 
    - Уже в каталоге создаются виртуальные машины. 
5. Создать сервисный аккаунт. 
    - От имени сервисного аккаунта уже будет работать Terraform.
    - Для работы через Terraform требуется выдать роль `iam.serviceAccounts.tokenCreator` созданному сервисному аккаунту. 
6. Создать авторизованный ключ от имени созданного сервисного аккаунта. Данный ключ так же потребуется для работы Terraform.

## <a id="terraform">Установка Terraform на локальную виртуальную машину Ubuntu.</a>  

Перед началом развёртывания виртуальных машин для хостинга сайта в облаке Yandex Cloud потребовалось установить и настроить terraform. Установить его можно через официальный репозиторий HashiCorp или вручную. Я использовал способ ручной установки Terraform, скачав бинарный файл с официального сайта и распаковал в путь `/usr/bin/`.

Все конфигурации поекта, используемые для выполнения задачи, храняться в репозитории в [отдельной директории проекта Terraform.](cloud-terraform/)

## <a id="tf_yc">Настройка Terraform для работы с YandexCloud</a>  
После установки необходимо настроить Terraform на работу с облаком Yandex Cloud. Проекты Terraform можно разделять каталогами. Terraform прочитывает все файлы *.tf внутри каталога, имя при этом не имеет значение. Это значит, что проект можно как поделить на различные сегменты, например `main.tf` и `network.tf`, так и сделать всё в одном файле.  

Для того, чтобы Terraform знал, с чем работать - ему нужно указать провайдера. Провайдер - это **мост** между Terraform и целевой платформой. В нашем случае провайдер указан в отдельном [файле](cloud-terraform/providers.tf). Информацию о провайдере можно взять с [официального сайта Terraform](https://registry.terraform.io/browse/providers) или же напрямую у [YandexCloud](https://yandex.cloud/ru/docs/terraform/tf-ref/overview).  

Помимо провайдера нужно указать **cloud_id** и **folder_id**. В нашем случае эти данные указаны в `providers.tf` в качестве переменных. Сами переменные хранятся в `variables.tf`, которого нет в данном репозитории. В `variables.tf.old` выставлен в качестве примера.

Публичный SSH ключ для подключения ко всем создаваемым машинам указан в `cloud-init.yml` файле.

## <a id="ansible">Установка Ansible и развёртывание ПО.  </a> 

Ansible устанавливается с помощью пакетного менеджера `sudo apt install ansible`. 
Создаётся отдельная директория проекта, где создаётся несколько файлов. 

`hosts.ini` - в нём указываются ip адреса хостов, с которыми будет вестись работа. Хосты могут быть разделены на группы. Чтобы явно не вводить ip адреса, а так же реализовать jump server - их можно указать в `.ssh/config`. В нашем случае так и сделано. 

`ansible.cfg` - в данном файле содержится конфигурация проекта. Он используется при запуске команд ansible из директории, где находится файл. 

`playbook.yml` содержит уже непосредственный список задач, которые необходимо выполнить на управляемых хостах. К примеру одна из таких задач указана ниже. 

```
- name: Настройка веб-сервера  # Имя, которе будет отображаться во время выполнения
  hosts: webservers            # Имя группы хостов, к которому нужно применить изменения
  become: true                 # Использовать ли root права? 

  roles:                       # Перечень групп задач, которые необходимо выполнить 
    - nginx
    - zabbix-agent
    - filebeat
```
 `roles` описаны в соответсвующем каталоге репозитория. Эти файлы последовательно говорят,  
 что сделать на хостах.   
 Помимо этого есть каталоги `group_vars`, в котором содержатся переменные. Например пароли.  
 Такие чувствительные переменные внесены в `.gitignore` этого репозитория. Почти каждый файл ролей и хостов закоментирован.
